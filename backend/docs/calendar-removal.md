# 캘린더 나가기와 삭제

## 정책

- 참여자: `POST /api/v1/calendars/{calendar_id}/leave` → 204.
- 만든 사람: `DELETE /api/v1/calendars/{calendar_id}` → 204.
- 만든 사람의 나가기는 409, 참여자의 전체 삭제는 403. 소유권 이전은 지원하지 않습니다.
- 참여자가 나가면 본인이 작성·가져온 공유 일정과 해당 가져오기 기록을 삭제합니다. 다른 사람 일정은 유지합니다. 새 참여자에게 탈퇴자의 일정이 노출되지 않도록 한 정책입니다.
- 나가면 기존 초대코드를 무효화합니다. 다시 참여하려면 만든 사람이 새 코드를 발급해야 합니다.
- 전체 삭제는 양쪽의 일정, 가져오기 출처, 멤버, 초대코드를 모두 삭제합니다. 복구 기능은 없습니다.
- Android 기기의 원본 일정은 변경하지 않습니다.

## 구현

`services/calendars.py`에서 캘린더 행 잠금 후 멤버십/역할을 확인합니다. 일정 읽기·저장·가져오기도 같은 캘린더 잠금을 먼저 얻어 나가기·삭제와 경합할 때 권한 확인 및 저장 순서를 보장합니다. 처리 중 실패하면 세션 트랜잭션이 롤백됩니다.

기존 FK CASCADE를 사용하므로 DB 마이그레이션은 없습니다. 계정 삭제 정책은 그대로입니다. 초대 이력 등에서 참조하는 계정은 캘린더를 나간 뒤에도 삭제가 제한될 수 있습니다.

Flutter 캘린더 목록 카드에 역할에 맞는 버튼을 표시합니다. 삭제 범위 확인 → API 호출 → 캘린더 목록/상세/일정 캐시 무효화 순서입니다. 처리 중 중복 클릭을 막고 오류가 발생하면 확인창에서 다시 시도할 수 있습니다. 상대방은 새로고침/앱 복귀 시 결과를 확인합니다. 이미 내려받은 화면을 원격에서 즉시 지우는 실시간 기능은 포함하지 않습니다.

## 검증

격리 DB에서 비회원/미인증/소유자 역할 제한, 탈퇴 후 접근 금지, 본인 일정만 삭제, 새 참여자의 목록, 가져오기 기록 연쇄 삭제, 일정 생성과 탈퇴 동시 요청, 이전 초대코드 무효화와 재초대를 검사합니다. Flutter 테스트는 삭제/나가기 확인·취소·오류 후 재시도와 목록 갱신을 검사합니다.
